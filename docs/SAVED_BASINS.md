# 引き込み領域の保存結果と再計算方法

## 1. 条件

結果は研究32のnf02_1。全台τp=1.16/1.18/1.20秒、τq=.02秒、P指令[.5,.4,.4,.4] pu、Bus5負荷コンダクタンス倍率2.461761102780045、k=1.02990です。事故はBus4の20 pu受動シャントを1.0秒に投入し、1.15秒で除去すると同時に線路4–5を開放します。

実事故軌道は研究31の保存時系列、背景の初期値応答は研究32の詳細モデル計算を利用しました。全281条件を新たに再計算したものではありません。

## 2. 2次元の座標から全状態を構成する方法

原点は事故後安定平衡点の遠方平均内部角−1.5548103219232832 rad。θはそこからの内部角差、Δfは60 Hzからの内部周波数偏差です。遠方群はBus2・3・7の等重み平均です。

このθは保存データ・初期値指定の内部座標です。今回追加したτp=0.1秒専用図（plot_tau010_basin.py）の表示は、無限大母線Bus6の位相0 radを基準とする平均内部位相に統一しました。表示値はθ−1.5548103219232832 radです。安定点は−1.554810322 rad、鞍点は−1.694255058 radに表示されます。--angle-reference equilibriumで以前の安定点基準の表示を再現できます。計算・分類・保存されたtheta_relative_radの定義は変更しません。

1. 事故後安定平衡点の全66変数を基準にする。
2. 遠方3台の内部角δを同じ量ずつ変更してθを合わせる。機間角差は保持する。
3. 遠方3台のPフィルタ状態を同じ量ずつ変更してΔfを合わせる。今回の単位・ゲインではΔf=1.2 mean(0.4−Pfilt) [Hz]。
4. その他46微分状態の初期値を基準状態の値にそろえる。Bus1、Qフィルタ、LCL、電圧・電流PI積分状態などを含む。
5. 14代数変数だけをNewton法で整合化する。52微分状態、指定座標、保持46状態が変更されていないことを確認する。
6. 初期化後は52微分状態を全て時間積分する。46状態を一定に拘束し続ける計算ではない。

この2次元断面と実事故除去状態の全状態は一致するとは限りません。鞍点も同じ2軸への投影で、断面上の点とは限りません。同じθ=−.125 rad、Δf=−.0025 Hzで、46状態の初期値を平衡点から事故除去状態へ変えると、3つのτ全てで負方向回転から回復へ変わる例を双方1000秒で確認済みです。

## 3. 格子と描画

初期粗格子はθ=[−.4,−.15,0,.4,.8,1.2,1.6] rad、Δf=[−.15,−.10,−.05,0,.05] Hz。平衡点・事故除去点近傍と分類の異なる点の間を細分化しました。各τの背景は88点、合計264点です。通常300秒、追加確認点は1000秒。各点の実評価時間をCSVに記録しています。

三角形の全頂点が同分類なら薄く着色し、混在する場合は斜線にしています。破線は回復/負回転ラベルを線形補間した0.5位置です。厳密な分離軌道や吸引域境界ではありません。未計算の内部点、狭い島、格子以下の構造は確認できていません。

再作図では保存された三角形をそのまま読み込み、再三角形分割や境界探索を行いません。元の時間サンプルにも追加間引きを行いません。

## 4. 分類と数値設定

回復：各機で末尾min(50秒,観測時間/3)の最大|Δf|<1e−4 Hz、角変動幅<.005 rad、安定根との角誤差<min(.002 rad,各機の安定根–鞍点角差の10%)。

負方向回転：総変位が−2回転を超え、観測後半60%を3分した全窓で−.2回転を超えて負方向に進み、平均回転速度<−1e−4回転/秒。有限時間分類であり、全状態の完全収束や永久回転を証明しません。元の分類では末尾に持続的な低電圧がある場合も別途確認しました。

Rodas5P、A：reltol=1e−9、abstol=1e−11、dtmax=.005秒。B：1e−10、1e−12、.0025秒。背景の通常保存間隔.05秒、各区間先頭20msは.0001秒。実事故の保存間隔は通常.02秒で、積分精度と保存刻みは別です。

元研究の代表2点のA/B比較では分類が一致し、300秒内部回転数の最大差は約1.89e−10回転でした。背景の全点で精度を比較したという意味ではありません。

## 5. 保存データで再作図

リポジトリ直下でPython依存をインストールした後：

```bash
python code/check_saved_basins.py
python code/plot_saved_basins.py
```

標準出力先はfigures/saved_results/conditional_basins/。別の出力先は `--output /path/to/output` を指定します。元の保存結果は変更しません。

### 事故中の軌道を重ねる

同梱の実事故時系列は事故除去後から始まります。事故中0.15秒の軌道も表示する場合は、リポジトリ直下で次を実行します。

```bash
julia --history-file=no --project=provenance code/run.jl fault_overlay.csv
python code/export_fault_trajectories.py
python code/plot_saved_basins.py
```

fault_overlay.csvは3時定数の事故前・事故中・事故後30秒を計算します。τp=1.20秒は既存smokeと同一なので、完了済みチェックポイントがあれば再利用します。export_fault_trajectories.pyは全66状態の事故前・事故除去・30秒終端とパラメータを参照値と照合し、事故中の選択した観測量をdata/fault_trajectories.csv.gzへ出力します。事故除去点が保存済みの事故後軌道の先頭と一致することも検査します。

このローカル出力がある場合、領域図に事故中の紫線・事故投入点の三角印を追加します。白丸は事故除去点、黒線は事故後軌道です。fault_on_comparison.pdf/pngには、事故中の位相–周波数軌道の拡大と周波数の時間波形を描きます。時刻は除去時を0秒とし、投入時は−0.15秒です。別のエクスポートを使う場合は `--fault-trajectories /path/to/file.csv.gz` を指定できます。出力がなければ従来どおり事故後のみを表示します。

背景は事故後系統の条件付き回復領域です。事故中には系統構成と方程式が異なるため、事故中の線が背景の色や破線を横切ることから回復・脱調を判定することはできません。また、τpの変更は事故除去時の全状態と事故後ダイナミクスの双方を変えます。回復例が増えただけでは引き込み領域の包含・拡大は確定しません。

### τp=0.1秒の軌道との比較

τq=0.02秒・事故時間0.15秒・負荷・指令を維持し、全GFMのτpだけを0.1秒にした事故応答を150秒まで計算できます。上記の事故中エクスポートを用意した後、次を実行します。

```bash
julia --history-file=no --project=provenance code/run.jl tau010.csv
python code/plot_saved_basins.py --additional-case tau010_T015_h150 --display-horizon 150 --output figures/tau010_comparison
```

4条件の領域図・事故中拡大図・事故後時系列・各機応答図を生成します。0.1秒の条件には引き込み領域の計算点がないため、背景を着色せず「Basin not sampled」と表示します。他のτの背景や境界を流用しません。追加ケースは全台パラメータ・事故後の安定根と鞍点・既存の安定平衡点との一致・事故除去時の座標の連続性を確認してから描画します。分類・各機指標はdata/results/tau010_T015_h150.jsonへ保存します。比較図の事故後時間軸は全条件150秒にそろえます。

### τp=0.1秒の粗い領域を段階計算する

```bash
julia --history-file=no --project=provenance code/run_tau010_basin.jl
python code/check_tau010_basin.py
python code/plot_tau010_basin.py
```

前節の0.1秒実事故計算で保存した事故後パラメータ・平衡点を使います。元の粗格子と同じθ7点×Δf5点の35初期値を、1つのJuliaプロセス内で順に処理します。初期値断面・52微分状態の保持・14代数変数の整合化は既存の定義と同じです。

まず30秒で既存と同じ各機の有限時間基準を評価します。未確定の点だけ終端状態から60秒、さらに150秒へ延長します。150秒でも未確定なら灰色で表示し、回復扱いにはしません。判定時間が点ごとに異なり、既存の300秒・1000秒評価と同じ観測時間ではありません。短時間の回復・回転分類は、それ以降の再脱調・再同期を排除するものではありません。

basin_recalculation/tau010_adaptive/に初期66変数、パラメータ、平衡点検証、判定履歴、各機指標、平均軌道、終端全状態、描画点・三角形を保存します。区間ごとの全状態履歴はJulia Serialization形式（.bin）で保持し、同じ入力・コードでの再開に使います。configuration.sha256が変わる場合は再利用を拒否します。モデル構築と初回コンパイルは全点で共有し、初期値ごとにJuliaを起動しません。

0.1秒の領域図専用の出力先はfigures/tau010_adaptive_basin/です。他条件の比較図・時系列・各機応答図はここへ生成しません。plot_tau010_basin.pyは終端の各機内部位相を参照平衡点と比較し、元の位相枝への回復26点と、遠方3台が−2πずれた枝への回復9点を区別します。既存の回復判定は2π周期なので、双方とも回復に含まれます。この分類を無スリップの安全領域とは呼びません。ひし形は鞍点の投影で、鞍点自身はこの初期値断面上にありません。今後の調べ方はTAU010_NEXT_STEPS.mdを参照してください。

### 安定平衡点と鞍点の両方を通る断面

従来の断面は、安定点から遠方3台の内部位相とPフィルタ状態だけを一様にずらし、その他46微分状態の初期値を固定する定義です。鞍点ではこの46状態のうち27状態も異なるため、従来の断面は鞍点を通りません。

両平衡点を通る断面は、52微分状態yに対して y(α,Δf)=y_s+α(y_u−y_s)+Δf v_f と定義します。y_sが安定点、y_uが鞍点、v_fは遠方3台のPフィルタ状態を変えて共通周波数偏差を1 Hz変化させる方向です。両根の周波数偏差は0で、v_fは位相を変えないので、保存座標θ=α θ_u、縦軸Δfを使えます。図の横軸は保存座標に安定点の実位相を加えたBus6基準です。位相は近い枝にそろえた保存根を使います。

α=0・Δf=0で安定点そのもの、α=1・Δf=0で鞍点そのものです。他の初期値では46状態もαに応じて変わります。14代数変数は各点で整合化するため、全66変数では一般に平面ではなく2次元曲面になります。初期化後は全52微分状態を動かします。

```bash
julia --history-file=no --project=provenance code/run_tau010_chord_basin.jl
python code/check_tau010_basin.py --section chord
python code/plot_tau010_basin.py --section chord --event-overlay
```

α=[−0.5,0,0.5,0.9,1,1.1,1.5]、Δf=[−0.05,−0.025,0,0.025,0.05] Hzの35点で、両根を格子に明示的に含めます。判定時間は30/60/150秒の段階方式。データはbasin_recalculation/tau010_chord/、図はfigures/tau010_chord_basin/に分けて保存します。slice_anchors.csvで両根の全66変数が元の根と一致することを検査し、slice_basis.csvで各変数の方向成分を保存します。鞍点から開始した点は通常の回復色に含めず、鞍点として表示します。

--event-overlayで既存のτp=0.1秒の事故中・事故後軌道を同じθ・Δf座標へ重ねます。左は全体、右は局所断面の拡大です。紫線は事故中、黒線は事故後、三角は投入、白丸は除去。未着色の領域は未計算です。軌道は座標投影であり、全状態がこの断面上にあることを示しません。断面だけの図を作る場合はこのオプションを外します。他条件の図は生成しません。

## 6. 選択した点を再計算

Julia・Python環境を用意し、Pythonの仮想環境を有効にして、リポジトリ直下で実行します。

```bash
julia --history-file=no --project=provenance code/run_basin.jl refine_00247 focus_00148
```

引数はdata/jobs.csvのcase列です。上の2点は回復／負回転の代表点で、各300秒を計算します。Pythonを明示する場合は `GFM_PYTHON=/path/to/python` を環境変数で指定します。

```bash
julia --history-file=no --project=provenance code/run_basin.jl --all
```

`--all` は保存された281点を順番に計算し直します。適応格子を新たに追加する機能はありません。単に図を確認する場合、この全点再計算は不要です。

初期値はresults/conditional_basins/data/initial_states.csv、パラメータは同data/references/parameters_*.csvから読みます。52状態保持・代数整合・座標誤差・全台時定数とP指令・安定根と鞍点の線形化を再確認します。

生の出力はcheckpoints/saved_basin_CASE/、再計算の監査・比較JSONはbasin_recalculation/です。これらをGit管理対象から除外しています。途中の完了区間は同じ条件・同じコードなら再利用します。入力・コードが変わると再利用を拒否するため、変更実験は新しい作業コピーを使ってください。元の保存結果は上書きしません。

## 7. 出典と共有準備での確認

provenance/sources.jsonに元のファイル識別情報を記録。各条件のJSON結果をoutcomes.jsonlへ、初期状態をinitial_states.csvへまとめました。元のマニフェストの時間延長用重複3行を整理し、281個の最終条件として保存しています。元マニフェストも保持しています。

作図用データ、全初期状態、分類表、実事故時系列、隠れ状態比較の整合性をPythonで確認し、再作図しました。さらに今回の入口から代表2点を再積分して保存結果と照合しました。結果はresults/conditional_basins/provenance/recalculation_check.jsonにあります。詳細GFMモデルの結果であり、EMT/PWM検証ではありません。
